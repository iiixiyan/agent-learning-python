## 核心项目写法示例

### 项目一：企业级知识库系统（重点项目）

**项目描述**：
> 基于 RAG 技术构建企业级知识库问答系统，支持 PDF/Word/Excel 等多格式文档解析，实现混合检索（向量+全文）+ Reranker 重排，问答准确率提升 40%。

**技术栈**：Python、FastAPI、LangChain、LangGraph、Milvus、ElasticSearch、PostgreSQL、Redis、BGE-Reranker、Docker

**个人职责与成果**（用 STAR 法则，量化成果）：

| 模块 | 具体工作 | 量化成果 |
|------|----------|----------|
| **文档解析模块** | 基于 unstructured + pypdf 实现 10+ 格式文档解析，支持表格、图片提取 | 解析准确率 95%+ |
| **检索优化** | 设计混合检索架构（向量检索 + BM25 全文检索 + BGE-Reranker 重排） | Top-5 召回率从 68% 提升至 92% |
| **异步流水线** | 基于 RabbitMQ 实现文档处理异步流水线，支持多阶段处理（解析→切分→向量化→索引） | 吞吐量提升 3 倍 |
| **系统架构** | FastAPI 后端 + PostgreSQL 存储 + Redis 缓存 + Milvus 向量库，Docker Compose 一键部署 | 支持 1000+ 并发 |
| **效果评估** | 构建 200+ 条测试集，用 LangSmith 做 RAG 评估 | 答案准确率从 65% 提升至 88% |

**项目亮点**（面试加分项）：

- 实现了 **Agentic RAG**，大模型自主决定检索策略（直接回答 / 检索 / 多轮检索）
- 支持**多轮对话记忆**，基于 Redis 实现短期记忆 + Mem0 长期记忆
- **全链路可观测**，LangFuse 追踪每次调用的 token、耗时、成本
- 实现了**权限控制**，基于 RBAC 模型做检索权限过滤
- 支持**父子分块**策略，子块检索、父块生成，提升上下文完整性

**技术栈**：Python、FastAPI、LangGraph、LangChain、Milvus、Redis、PostgreSQL、BGE-Reranker、Docker

**个人职责与成果**：

| 模块 | 具体工作 | 量化成果 |
|------|----------|----------|

| **FAQ 直接匹配** | 高频问题用向量匹配直接返回标准答案，不走大模型生成 | 响应时间从 3s 降至 200ms |
| **混合检索** | 向量 + BM25 混合检索 + Reranker 重排，产品知识库 + 政策文档 | 召回率 90%+ |
| **Human in the Loop** | 复杂问题自动创建工单转人工，基于 LangGraph interrupt/resume 实现 | 人工介入率降低 60% |

- **FAQ + RAG 混合模式**：高频问题直接匹配，复杂问题走 RAG 生成，兼顾效率和准确性

- **全链路观测**：LangFuse 追踪每次对话的完整链路，支持问题排查和效果优化

## 简历常见问题

### ❌ 错误写法

```
做了一个 RAG 项目，用了 LangChain 和向量数据库，能回答问题。
```

**问题**：太笼统，没有量化成果，没有技术细节，没有个人职责。

### ✅ 正确写法

```
企业级知识库 RAG 系统
- 基于 LangChain + Milvus 构建 RAG 问答系统，支持 PDF/Word 多格式文档
- 实现混合检索（向量+BM25）+ BGE-Reranker 重排，Top-5 召回率 92%
- 用 FastAPI 封装 RESTful API，Redis 缓存热点问题，P99 响应 < 2s
- 构建 200+ 条评估集，答案准确率 88%，支持 1000+ 并发
```

### 简历避坑指南

| 避坑点 | 说明 | 正确做法 |
|--------|------|----------|
| **只列技术名词** | "用了 LangChain、Milvus、FastAPI" | 说明用这些技术做了什么，带来了什么提升 |
| **没有量化成果** | "提升了检索效果" | "Top-5 召回率从 68% 提升至 92%" |
| **项目描述太笼统** | "做了一个 RAG 系统" | 说明业务场景、解决了什么问题、系统规模 |
| **个人职责不清晰** | "参与了项目开发" | 明确你负责哪个模块，做了什么优化 |
| **技术栈不匹配** | 写了很多不相关的技术 | 只写和 RAG/Agent 相关的技术，突出重点 |
| **项目数量太多** | 列了 5-6 个小项目 | 重点写 1-2 个核心项目，其他简写 |
| **没有亮点** | 都是基础功能 | 突出 Agentic RAG、多模态、权限控制、评测体系等加分项 |

## 面试高频问题（RAG 方向）

### 基础题

**1. RAG 的完整流程是什么？**

答：分为离线构建和在线问答两个阶段。
- **离线构建**：文档加载→解析清洗→分块→向量化→存入向量库→构建 BM25 倒排索引
- **在线问答**：用户问题→Query 改写→混合检索（向量+关键词）→RRF 融合→Reranker 重排→拼接 Prompt→大模型生成回答

**2. 如何提升 RAG 准确率？**

答：从多个层面优化：
- **切分策略**：按语义/章节切分，父子分块，合理设置块大小和重叠
- **检索优化**：混合检索（向量+全文），加 Reranker 重排，Query 改写
- **Prompt 优化**：强约束模型依据上下文回答，要求标注引用，开启拒答机制
- **多轮检索**：Agentic RAG，大模型自主判断信息是否充足，不足时多轮检索
- **评估迭代**：构建测试集，持续评估和优化

**3. 向量数据库怎么选？**

| 规模 | 推荐 | 说明 |
|------|------|------|
| **小规模/原型** | FAISS、Chroma | 本地文件存储，简单易用 |
| **中规模/生产** | PGVector | PostgreSQL 插件，和业务数据一起管理 |
| **大规模/高性能** | Milvus、Qdrant、Pinecone | 分布式向量数据库，支持亿级向量 |

**4. 什么是 Agentic RAG？和普通 RAG 的区别？**

答：普通 RAG 是固定流程（检索→生成），Agentic RAG 让大模型自主决定：
- 是否需要检索（简单问题直接回答）
- 检索什么（Query 改写、多轮检索）
- 信息是否充足（不足时继续检索）
- 用 LangGraph 实现决策循环，形成规划→工具调用→结果评估→迭代重试的闭环

**5. 如何评估 RAG 效果？**

答：构建测试集（问题+标准答案+相关文档），从两个维度评估：
- **检索层**：Recall@K（召回率）、Precision@K（精确率）、MRR（排序质量）、Hit@K（命中率）
- **生成层**：Faithfulness（忠实度/有无幻觉）、Answer Relevancy（答案相关性）、Answer Completeness（答案完整性）、Context Utilization（上下文利用率）
- 工具：RAGAS、TruLens、LangSmith、LangFuse

### 进阶题

**6. 什么是 RRF 算法？为什么需要它？**

答：RRF（Reciprocal Rank Fusion，倒数排名融合）。向量检索分数范围 0~1，BM25 分数没有上限，二者不能直接融合。RRF 不看原始分数，只根据排名计算融合分值，公式：`score = 1/(k + rank)`。可以有效融合多路召回结果。

**7. 什么是父子分块策略？有什么好处？**

答：先将长文档切分为较大的父块，再在父块内切分更小的子块。子块做向量化检索，父块存原文做生成。通过 parent_id 关联。好处：
- 子块小，检索精准，减少召回噪声
- 父块大，上下文完整，缓解幻觉
- 解耦检索和生成分块，兼顾精准度和完整性

**8. 如何降低大模型幻觉？**

答：从 4 个层面处理：
- **知识层**：RAG 检索、混合检索、Reranker、相似度阈值、Agentic RAG
- **提示词层**：强约束依据上下文回答、标注引用、拒答机制
- **模型层**：选事实性好的模型、垂直领域微调
- **校验层**：二次事实核查、比对原文、拦截修正

**9. RAG 如何做权限过滤？**

答：基于 RBAC 模型。文档切片入库时，chunk 继承父文档的权限配置（允许访问的角色、是否公开），作为元数据存入向量库和全文检索库。用户检索时，先获取用户角色集合，基于角色元数据筛选，只在有权访问的切片范围内检索，从源头拦截无权限内容。

**10. 为什么 Claude Code 不用 RAG 检索代码，而是用 grep？**

答：两个原因：
- **代码需要精确匹配**：函数名、类名、变量名、报错字符串是标识符，适合关键词精确查找，不适合语义模糊匹配
- **代码库高频变更**：RAG 索引容易过时，grep 直接读磁盘实时文件，结果和源码完全同步
- Claude Code 现在用 Agentic Search，大模型自主决定用 grep（内容检索）、glob（文件名匹配）、read（读取文件），信息不足时循环迭代

## 学习要点

1. **RAG 项目简历要量化成果**：准确率、召回率、并发数、响应时间、吞吐量，用数字说话
2. **技术栈要写具体用途**：不要只列名词，说明用这些技术做了什么，带来了什么提升
3. **项目描述用 STAR 法则**：情境(S)→任务(T)→行动(A)→结果(R)，重点突出你做了什么优化
4. **核心项目详细写**：1-2 个核心项目写详细（模块、职责、成果、亮点），其他项目简写
5. **突出加分项**：Agentic RAG、多模态、权限控制、评测体系、Human in the Loop、全链路观测
6. **准备高频面试题**：RAG 流程、提升准确率、向量库选型、Agentic RAG、RAG 评估、RRF、父子分块、降低幻觉、权限过滤
7. **理解原理比会用框架重要**：面试会问为什么这样做，而不是怎么用 LangChain
8. **简历要和岗位匹配**：投 RAG 岗位就突出 RAG 相关经验，不要写不相关的技术
9. **项目要有业务场景**：说明解决了什么业务问题，系统规模多大，不是纯技术 demo
10. **持续优化迭代**：构建测试集，持续评估和优化，这本身就是很好的项目亮点
