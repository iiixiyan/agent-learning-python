## 设计目标

企业级知识库系统需要存储：

| 数据类型 | 说明 | 存储选型 |
|----------|------|----------|
| **文档元数据** | 名称、类型、大小、上传者、状态 | PostgreSQL |
| **文档内容** | 解析后的纯文本、分块数据 | MongoDB / PostgreSQL JSONB |
| **向量索引** | 文本向量，用于语义检索 | PGVector / Milvus |
| **用户信息** | 用户、角色、权限 | PostgreSQL |
| **操作日志** | 上传、下载、删除、审核日志 | PostgreSQL |
| **对话历史** | AI 问答会话、消息 | PostgreSQL |

**选型**：PostgreSQL 存结构化数据（文档元数据、用户、权限、日志），MongoDB 存灵活的文档内容和分块数据（JSON 结构灵活）。

**简化方案**：小项目可以只用 PostgreSQL（JSONB 存灵活数据 + PGVector 存向量），不用 MongoDB，减少维护成本。

## PostgreSQL 表设计

### 1. 用户表（users）

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    nickname VARCHAR(50),
    avatar_url VARCHAR(500),
    phone VARCHAR(20),
    department_id INT REFERENCES departments(id),
    status VARCHAR(20) DEFAULT 'active',  -- active / disabled
    last_login_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_users_username ON users(username);
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_department ON users(department_id);
```

```sql
    allowed_users INT[],  -- 允许访问的用户ID数组
    error_message TEXT,  -- 解析失败时的错误信息
```

### 9. 向量存储（PGVector 方案）

```sql
-- 启用 pgvector 扩展
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE document_chunks (
    id SERIAL PRIMARY KEY,
    document_id INT REFERENCES documents(id) ON DELETE CASCADE,
    chunk_index INT NOT NULL,  -- 分块序号
    parent_chunk_id INT,  -- 父子分块：父块ID
    content TEXT NOT NULL,
    embedding vector(1536),  -- text-embedding-3-small 维度
    embedding_model VARCHAR(50),  -- 使用的嵌入模型
    metadata JSONB,  -- 页码、章节、字符位置等
    token_count INT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(document_id, chunk_index)
);

-- IVFFlat 索引（适合大规模数据）
CREATE INDEX ON document_chunks USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);

-- HNSW 索引（查询更快，构建更慢，适合数据量不大但查询频繁）
-- CREATE INDEX ON document_chunks USING hnsw (embedding vector_cosine_ops) WITH (m = 16, ef_construction = 64);

CREATE INDEX idx_chunks_document ON document_chunks(document_id);
CREATE INDEX idx_chunks_parent ON document_chunks(parent_chunk_id);
```

## 为什么 PostgreSQL + MongoDB？

| 数据类型 | 存储 | 原因 |
|----------|------|------|
| 用户、文档元数据、权限、日志 | PostgreSQL | 结构化、需要事务、关系查询 |
| 文档原始内容、分块详情 | MongoDB | 结构灵活、JSON 嵌套、大文本 |
| 向量索引 | PGVector 或 Milvus | 向量检索专用 |
| 缓存、会话、队列 | Redis | 高性能 KV |

### 简化方案（推荐小项目）

只用 PostgreSQL，不用 MongoDB：
- JSONB 存灵活的文档内容和分块元数据
- PGVector 存向量
- 减少维护成本，简化架构

```sql
-- PostgreSQL JSONB 方案示例
CREATE TABLE document_contents (
    id SERIAL PRIMARY KEY,
    document_id INT REFERENCES documents(id) ON DELETE CASCADE,
    raw_text TEXT,
    markdown TEXT,
    structure JSONB,  -- 文档结构
    images JSONB,     -- 图片列表
    tables JSONB,     -- 表格列表
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

```python
"""
models.py - SQLAlchemy 模型定义
"""
from sqlalchemy import create_engine, Column, Integer, String, Text, BigInteger, Boolean, DateTime, ARRAY, ForeignKey
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import relationship, sessionmaker
from datetime import datetime
from pgvector.sqlalchemy import Vector
from dotenv import load_dotenv
import os

load_dotenv()

Base = declarative_base()


class User(Base):
    __tablename__ = 'users'

    id = Column(Integer, primary_key=True)
    username = Column(String(50), unique=True, nullable=False)
    email = Column(String(100), unique=True, nullable=False)
    password_hash = Column(String(255), nullable=False)
    nickname = Column(String(50))
    avatar_url = Column(String(500))
    department_id = Column(Integer, ForeignKey('departments.id'))
    status = Column(String(20), default='active')
    last_login_at = Column(DateTime)
    created_at = Column(DateTime, default=datetime.now)
    updated_at = Column(DateTime, default=datetime.now, onupdate=datetime.now)

    documents = relationship("Document", back_populates="uploader")


class Department(Base):
    __tablename__ = 'departments'

    id = Column(Integer, primary_key=True)
    name = Column(String(100), nullable=False)
    parent_id = Column(Integer, ForeignKey('departments.id'))
    sort_order = Column(Integer, default=0)
    created_at = Column(DateTime, default=datetime.now)


class Document(Base):
    __tablename__ = 'documents'

    id = Column(Integer, primary_key=True)
    title = Column(String(200), nullable=False)
    file_name = Column(String(255), nullable=False)
    file_type = Column(String(20), nullable=False)
    file_size = Column(BigInteger, nullable=False)
    file_url = Column(String(500), nullable=False)
    file_hash = Column(String(64))
    status = Column(String(20), default='pending')
    parse_progress = Column(Integer, default=0)
    chunk_count = Column(Integer, default=0)
    word_count = Column(Integer, default=0)
    summary = Column(Text)
    uploader_id = Column(Integer, ForeignKey('users.id'))
    category_id = Column(Integer, ForeignKey('categories.id'))
    department_id = Column(Integer, ForeignKey('departments.id'))
    tags = Column(ARRAY(String))
    is_public = Column(Boolean, default=False)
    allowed_roles = Column(ARRAY(Integer))
    allowed_users = Column(ARRAY(Integer))
    error_message = Column(Text)
    created_at = Column(DateTime, default=datetime.now)
    updated_at = Column(DateTime, default=datetime.now, onupdate=datetime.now)

    uploader = relationship("User", back_populates="documents")
    chunks = relationship("DocumentChunk", back_populates="document", cascade="all, delete-orphan")


class DocumentChunk(Base):
    __tablename__ = 'document_chunks'

    id = Column(Integer, primary_key=True)
    document_id = Column(Integer, ForeignKey('documents.id', ondelete='CASCADE'))
    chunk_index = Column(Integer, nullable=False)
    parent_chunk_id = Column(Integer)
    content = Column(Text, nullable=False)
    embedding = Column(Vector(1536))  # PGVector 向量类型
    embedding_model = Column(String(50))
    metadata = Column(Text)  # JSON 字符串
    token_count = Column(Integer)
    created_at = Column(DateTime, default=datetime.now)

    document = relationship("Document", back_populates="chunks")


# 数据库连接
DATABASE_URL = os.getenv("DATABASE_URL", "postgresql://user:password@localhost:5432/knowledge_base")
engine = create_engine(DATABASE_URL, pool_size=10, max_overflow=20)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)


def init_db():
    """初始化数据库表"""
    Base.metadata.create_all(bind=engine)
    print("✅ 数据库表初始化完成")


if __name__ == "__main__":
    init_db()
```

### 向量检索示例

```python
"""
vector_search.py - PGVector 向量检索示例
"""
from sqlalchemy import text
from models import SessionLocal, DocumentChunk


def search_similar_chunks(query_embedding, top_k=5, document_ids=None):
    """
    向量相似度检索

    Args:
        query_embedding: 查询向量 (list of float)
        top_k: 返回数量
        document_ids: 限定文档ID范围（权限过滤）

    Returns:
        list: 相似分块列表
    """
    db = SessionLocal()
    try:
        # 构建查询
        query = text("""
            SELECT id, document_id, chunk_index, content,
                   1 - (embedding <=> :query_embedding) as similarity
            FROM document_chunks
            WHERE (:document_ids IS NULL OR document_id = ANY(:document_ids))
            ORDER BY embedding <=> :query_embedding
            LIMIT :top_k
        """)

        result = db.execute(query, {
            "query_embedding": str(query_embedding),
            "top_k": top_k,
            "document_ids": document_ids,
        })

        chunks = []
        for row in result:
            chunks.append({
                "id": row.id,
                "document_id": row.document_id,
                "chunk_index": row.chunk_index,
                "content": row.content,
                "similarity": float(row.similarity),
            })

        return chunks

    finally:
        db.close()


# 使用示例
if __name__ == "__main__":
    # 假设 query_embedding 是通过 Embedding 模型生成的向量
    query_embedding = [0.1] * 1536  # 示例向量

    # 全库检索
    results = search_similar_chunks(query_embedding, top_k=5)
    print(f"找到 {len(results)} 个相似分块")
    for r in results:
        print(f"  - 文档{r['document_id']} 分块{r['chunk_index']}: 相似度{r['similarity']:.4f}")

    # 限定文档范围（权限过滤）
    results = search_similar_chunks(query_embedding, top_k=5, document_ids=[1, 2, 3])
    print(f"\n权限过滤后找到 {len(results)} 个相似分块")
```

## 索引设计最佳实践

| 表 | 索引类型 | 字段 | 说明 |
|----|----------|------|------|
| documents | B-Tree | status | 按状态筛选（pending/parsed/failed） |
| documents | B-Tree | uploader_id | 按上传者查询 |
| documents | B-Tree | department_id | 按部门权限过滤 |
| documents | B-Tree | created_at DESC | 按时间排序 |
| documents | GIN | tags | 数组标签查询 |
| documents | GIN | to_tsvector('simple', title) | 全文搜索标题 |
| document_chunks | IVFFlat/HNSW | embedding | 向量相似度检索 |
| document_chunks | B-Tree | document_id | 按文档查询分块 |
| messages | B-Tree | conversation_id | 按会话查询消息 |
| operation_logs | B-Tree | user_id, created_at DESC | 用户操作日志查询 |

### 向量索引选择

| 索引类型 | 构建速度 | 查询速度 | 内存占用 | 适用场景 |
|----------|----------|----------|----------|----------|
| **IVFFlat** | 快 | 中 | 低 | 大规模数据（百万级以上） |
| **HNSW** | 慢 | 快 | 高 | 数据量不大但查询频繁 |
| **无索引（顺序扫描）** | 最快 | 慢 | 最低 | 数据量小（万级以下） |

## 学习要点

1. **企业级知识库用 PostgreSQL 存结构化数据**，MongoDB 存灵活的文档内容；小项目可以只用 PostgreSQL（JSONB + PGVector）
2. **文档状态机设计很重要**：pending→parsing→parsed→failed，审核状态独立，任务表记录解析进度
3. **权限设计是企业级必备**：RBAC 三级权限（页面/菜单/按钮）+ 数据权限隔离（部门/角色/用户），功能权限与数据权限双重隔离
4. **向量存储可以用 PGVector（简单）或 Milvus（大规模）**，PGVector 适合中小规模，Milvus 适合亿级向量
5. **对话历史和消息分开存储**，消息表用 sources 字段记录引用来源，token_usage 记录消耗，rating 记录用户反馈
6. **操作日志是合规必备**：记录用户操作、IP、User-Agent，支持审计和安全追溯
7. **父子分块通过 parent_chunk_id 关联**，子块做检索、父块做生成，提升上下文完整性
8. **索引设计影响查询性能**：B-Tree 用于等值和范围查询，GIN 用于数组和全文搜索，IVFFlat/HNSW 用于向量检索
9. **任务表用于异步处理追踪**：文档解析、向量化、索引构建都是异步任务，任务表记录状态和进度
10. **文件哈希用于去重**：相同文件只存一份，节省存储空间
